White paper apprentix.eu · October 2026

Europe’s apprenticeship data, gathered, checked and explained, every week

Apprentix brings together what Cedefop, Eurostat, the OECD, UNESCO, the European Commission and ten national statistics offices publish about apprenticeships and vocational education and training. It checks every figure, keeps a record of where each one came from, and turns the data into pages that policy makers, researchers, employers and young people can use. This paper explains what the site does, where its data comes from, and how it runs with very little manual work.

01 · The problem

The data exists, but it is scattered

Anyone trying to understand apprenticeships in Europe has to visit many places. Cedefop alone publishes key indicators in a spreadsheet, scheme descriptions in an online database, a timeline of national policies, a regional skills index, skills forecasts and qualification frameworks, each in its own tool and format. Eurostat, the OECD and UNESCO publish further statistics through their own interfaces. National statistics offices publish apprentice counts that cannot be compared directly between countries. The European Commission publishes Erasmus+ project lists as files of around 90 MB each.

There is also a gap that most people do not expect. No EU-wide statistic counts apprentices. Open, machine-readable national apprentice statistics exist for only nine countries. Apprentix says this plainly on its Insights page, and it treats the national series with care because each one counts something slightly different.

Apprentix does four things with this material:

  • Gathers it automatically wherever the publisher allows, and by careful hand-curation where it does not.
  • Checks it against fixed rules before anything is published.
  • Links it: a country, a scheme, a qualification, an occupation and an indicator are connected, so a reader can move from one to the next.
  • Explains it in plain language, with the method, the caveats and the source shown next to every figure.

03 · Sources

Where the data comes from

Apprentix tracks 32 sources. Twenty-two have an automated connector: a small program written for that one source, which knows where its data lives and how to read it. Twenty of these run every week. Two are switched off and will stay off until their publishers give permission. The other ten sources cannot be read by a program, either because the publisher’s website refuses automated visits or because the material is only published as a document. Those are curated by hand, on a schedule, and the site says so wherever their data appears.

In plain wordsPublishers offer data in different ways. An API is a door built for computers: a program asks a precise question and gets a precise answer. A file download is a spreadsheet or table that is replaced when new figures come out. SPARQL is the query language of linked-data registers such as Europass and the EU Publications Office. SDMX and JSON-stat are standard formats that official statisticians use to exchange tables. Apprentix speaks all of them.

Rules for reading other people’s websites

  • Every request names the project and gives its address, so publishers can see who is asking.
  • Requests are paced, and a refused request is retried later with growing pauses.
  • A website that refuses programs is never worked around. Its data is read in a browser by a person instead, or left out.
  • A source that needs permission is skipped in the code until permission exists.
  • Large files are downloaded only when their size shows they have changed.
  • No personal data is read, even when a file contains it.
04 · Automation

The weekly cycle, step by step

Every Monday at 05:17 UTC an automated job starts on GitHub’s servers. It runs the whole process below without anyone watching. A full rebuild of the 341 pages takes under a minute; most of the time goes on downloading.

  1. FetchEach of the 20 live connectors runs on its own. If one source is down, the others carry on.
  2. Keep the originalThe file as the publisher sent it is stored with the date. A new copy is kept only if the content changed.
  3. Put in one shapeCountry codes, years, units and statistical flags are written the same way for every source.
  4. CheckEach file is tested against a written schema and a list of rules. One error stops publication.
  5. BuildPages, charts, findings, quizzes, feeds, the catalogue and share images are regenerated.
  6. PublishThe result is saved with a note of what changed, and the web server picks it up within minutes.
  7. WatchNew datasets, overdue releases and refused downloads are listed for a person to look at.

When a publisher changes something

Each connector checks that a file looks the way it expects: the right sheets, the right country list, the right column headings. Examples from the code: “RESET workbook layout changed”, “BA workbook: expected Germany and 16 Länder”. If anything is off, that connector stops before it writes. The previous, good data stays online, the failure appears on the public Data & sources page, and the weekly job is marked as failed so it gets attention.

When new figures arrive

Apprentix keeps a fingerprint of every published series and record. When a fingerprint changes, it writes a dated entry in plain language: a new year of data, a revision, new records, a policy that moved stage, a new indicator. Example: “Germany: 1,211,844 apprentices in 2025.” These entries appear on the home page, on each country page and in the news feeds. Nothing is changed silently.

The source watch

A second program reads Cedefop’s entries on data.europa.eu, Eurostat’s list of tables and the national portals, looking for new apprenticeship and VET data. It also knows each source’s release rhythm (KIVET yearly, the skills forecast every six months, RESET every two years) and flags any release that is late. Everything it finds goes into one public to-do note, which closes itself when the list is empty.

Nothing moves unless the data moves

The “Last updated” date on the site is the date of the newest original file, not the date the job ran. A week in which no publisher changed anything produces no changes at all. Because of this, the project’s history is also an exact log of when each figure entered the site.

Statistical flags travel with the numbers. When Eurostat marks a value as a break in series (b), an estimate (e), provisional (p) or of low reliability (u), the flag is shown in Apprentix’s tables, and the quiz leaves such values out. Comparability notes appear where they matter: the financing data is dated 2016–17 on every page that uses it, and national series are fenced off with a “What is counted” panel for each of the nine countries. Each panel says whether the figure is a count on a date or over a period, what it includes and leaves out, and what it is good for.

06 · Safeguards

What stops bad data from going live

A written contract for every file

Each indicator must match a published schema: an identifier, title, description, unit, topic, full origin, series and coverage. Country codes must be known, every value must be declared, and a CSV copy must exist. Each dataset is checked the same way: record identifiers must be unique and record counts must match.

Validation before publication

The weekly job saves nothing unless the checker passes. The current site passes with “Checked 112 indicators and 11 datasets: 0 error(s)”. A second automatic check runs on every change to the code and fails if any page is out of date with its data.

Failures stay contained

A broken source keeps its last good data and shows its status on the Data & sources page. A stale fallback copy raises a warning. One bad source never takes down the others.

Hand-curated data is guarded too

The program that merges Cedefop’s scheme answers stops if a scheme uses an answer option it has not seen before, so a new questionnaire option cannot be mislabelled. Scheme descriptions were checked against Cedefop’s fiche text on 1 October 2026.

Reproducible to the byte

The same data always produces the same site. A full rebuild in a fresh copy produced zero differences from the published files. Software versions that affect output are pinned exactly, so even the 303 share images come out identical.

Permission written into the code

Sources that require the publisher’s permission are marked in the code and skipped until it is given. Two connectors wait in this state today.

09 · Method

Rules for fair comparison, written into the code

Comparing countries is easy to do badly. Apprentix applies the cautions a statistician would apply, every time and in the same way, because they are part of the program.

Better, worse, or just different

For each measure the code records whether higher is better (work-based learning, graduate employment), lower is better (early leavers, young people not in employment or education, youth unemployment), or neither (the share of pupils in VET). Only the first two get a “better” or “worse” chip. Counts and money get no EU comparison at all, because the EU figure is a total.

A strict country scorecard

In Country vs country, a measure counts only if it has a direction, both countries have the same indicator, and their years are at most one apart. The result is neutral: “Germany is ahead on 7 of 10 comparable measures; Austria on 3.” No winner is declared on money or policy counts, which depend on country size.

A fair quiz

Higher or lower? uses only harmonised indicators, countries in the European Economic Area, the same year and the default breakdown. Values flagged as unreliable, defined differently, or broken in series are left out. The gap must be at least 5% and above a minimum per unit, such as 2 percentage points. The question always asks which is “higher”, never which is “better”.

Sensible defaults

An indicator opens on the latest year that covers at least 60% of the countries of its best year, so a reader is not shown a map with three countries on it. Insights use simple, robust statistics (medians, counts, rank correlations) and say plainly that a link between two figures across countries does not prove that one causes the other.

10 · Generated text

Words written by the data, not by hand

Most websites go out of date because their text is written once and the data moves on. On Apprentix, much of the text is generated from the data at every build, using rules a person wrote and checked. When the data changes, the sentences change with it.

12 · Artificial intelligence

Ask Apprentix: an assistant that can only quote the site

Ask Apprentix answers questions in plain language, in the reader’s own language, using only the site’s published data. It is built and tested, and ready to switch on. Today the page says “The assistant isn’t switched on yet.”

A general chatbot answers from memory and can invent figures. Ask Apprentix is designed so that it cannot: the model must look things up, and the sources shown under each answer come from the look-ups, not from the model.

1 · Question“How do apprentices in Austria and France compare on pay?”
2 · Look-upUp to 5 rounds, 4 look-ups each: search the site, get a country, get an indicator, query records, list datasets.
3 · Apprentix data onlyThe look-ups read the same JSON files the website uses, including the 2,040-passage search index.
4 · AnswerEvery figure, scheme, date and definition must come from a look-up, with the publisher and year named.
5 · SourcesListed by the system from what was actually read, so they cannot be invented.

Rules the assistant must follow

  • If the data does not cover a question, it says “Apprentix’s data does not cover this.”
  • General background goes in a separate paragraph headed “Beyond Apprentix’s data”, with no figures, dates or links.
  • It respects the site’s caveats: national counts are not comparable, and the financing data is from 2016–17.
  • It gives no legal, financial or career advice, and ignores instructions hidden inside questions.

Privacy, cost and control

  • The question goes from the browser to a small program on Cloudflare’s network, which holds the only key to the language model. The key never reaches the browser or the code repository.
  • No cookies, no log of questions, and the conversation exists only in the open page. Readers are told not to enter personal data.
  • The model is reached through OpenRouter (currently xAI’s Grok) and can be replaced by any model that can use tools. A setting restricts it to providers that do not keep prompts.
  • Hard limits: 10 questions a minute per visitor, 1,000 questions and 3 million tokens a day.
  • 29 automated tests cover the search, the look-ups, the limits and the full question-and-answer loop.
In plain wordsA language model is software that writes text by predicting likely words. On its own it can sound sure and still be wrong. Grounding means making it answer only from documents it has been given, and tool use means letting it look those documents up step by step, the way a researcher checks a reference.
13 · Engineering

How it is built: light, fast and durable

A site made of plain files

The website is a set of ordinary files: no database, no user accounts, no server program that can fail at night. This makes it fast, cheap to run, hard to attack and easy to archive. It is served by Laravel Forge, behind Cloudflare’s network, and updates within minutes of each new version.

The pages use plain HTML, CSS and JavaScript (about 6,000 lines across 25 modules) with no framework. Every chart is drawn by the site’s own code. No charting library is used.

A data pipeline in Python

About 17,600 lines of Python in 64 files, with only four outside packages: one to read spreadsheets, one to check files against their schemas, one for secure connections and one to draw images. Fewer dependencies mean fewer things that break on their own.

The weekly job runs on GitHub Actions. The code and its full history are public. The code was written with an AI programming assistant (Anthropic’s Claude Code), under the author’s direction and review.

Readable without JavaScript

Country, indicator, dataset, occupation, story, insight, glossary and financing pages are complete without JavaScript. Their charts are drawn when the site is built, with a data table beside each. Interactive features are added on top. This matters for search engines, slow connections, archiving and assistive technology.

Accessible and calm

A skip link, labelled regions, keyboard play in the games, text alternatives for symbols, and a data table behind every chart. Animation stops for readers who ask their device for less motion. Dark mode follows the reader’s device. A formal accessibility audit is planned.

Stable while it loads

Pages are built so that nothing jumps as they load. Headline numbers are written into the page in advance, chart space is reserved, and fallback fonts are matched in width to the final fonts. In a test on a slow mobile connection with an empty cache, every page measured stayed under 0.1 on Google’s layout-shift score, the threshold Google treats as good. Before this work, some pages scored up to 0.45.

Design that can be switched back

The current look was chosen from six proposals in October 2026. One setting returns the whole site to its previous design. Each release stamps its style and script files with a content fingerprint, so a browser never mixes a new page with old styles.

14 · Human work

Where people still come in

Apprentix is designed so that routine work needs no one. Human time goes where judgement is needed, or where a publisher’s website does not allow programs.

Fully automatic, every week

  • Fetching from all 20 live sources
  • Keeping and fingerprinting every original
  • Checking every file against its rules
  • Rebuilding all 341 pages, charts, insights, stories, quizzes and facts
  • The change log and 43 news feeds
  • The data catalogue, data package and search index
  • Publishing, and marking the run as failed if any source failed
  • Watching for new and overdue releases

Needs a person

  • Re-reading the five Cedefop databases whose website refuses programs, and the yearly check of the scheme fiches
  • Updating a link when Cedefop renames a file for a new release (the watch flags it when a release is late)
  • Writing a connector when the watch finds a new dataset worth adding
  • Checking the hand-kept lists, such as the official apprenticeship services for each country
  • Asking publishers for permission, and switching gated sources on
  • Making a release on Zenodo
15 · Assessment

Why this is hard to copy

Twenty data dialects in one shape

Spreadsheets, statistical APIs, linked-data registers, PDF tables and national portals, each with its own codes and habits, all brought into one schema with full provenance.

Why hardEach source has quirks that only show up in use: hourly limits, banned query words, renamed files, columns that move.

A site that rewrites itself

Insights, stories, myths, facts, quizzes and scorecards are recomputed every Monday, and their wording follows the results.

Why hardEach finding must be written as a rule that stays true, or switches its wording, whatever the data does.

Statistical caution as code

Flags, breaks in series, coverage rules, year matching and fenced-off national series are applied everywhere in the same way.

Why hardIt takes statistical judgement as well as programming, and one slip produces a misleading chart.

The occupation lens

18 occupations matched across 24,768 qualifications in their original languages from 14 national registers, joined to ESCO, schemes and job outlooks.

Why hardMatching titles across languages without false matches needed patterns checked by hand against every hit.

Cedefop’s coding, turned into guidance

The 34 coded answers per scheme become portraits, learner paths, a matching tool that explains itself, and a comparison matrix.

Why hardIt requires understanding what each answer means for a learner, then saying it without overstating it.

Provenance down to the byte

Every figure leads to a dated original with a digital fingerprint, a licence and a citation.

Why hardProvenance has to be designed in from the first line. It cannot be added later.

Ready for European portals

A DCAT-AP catalogue, a Frictionless package, schema.org labels and a DOI, produced automatically every week.

Why hardThese standards are strict and rarely implemented by projects of this size.

No servers to keep alive

No database, no accounts, no tracking, and pages that read without JavaScript. The site can be copied and archived as it is.

Why hardGiving up a database means solving search, comparison and change tracking in other ways.

17 · Reference

Terms used in this paper

API
A door a website offers to programs, so they can ask for data directly instead of reading pages meant for people.
Connector
A small Apprentix program written for one source. It knows where the data is and how to read it, and checks that it still looks right.
Schema
A written description of what a valid file must contain. Files that do not match are rejected.
Provenance
The record of where a figure came from: publisher, table, date, licence and original file.
SHA-256 fingerprint
A code computed from a file’s contents. Any change to the file changes the code, so it proves the file is the original.
Static site
A website made of finished files, prepared in advance, rather than pages put together by a server for each visitor.
Deterministic
Always producing the same result from the same input. It makes every change traceable to a change in the data.
JSON, CSV
Two common file formats for data. CSV opens in a spreadsheet; JSON is easier for programs.
SPARQL
A query language for linked-data registers, such as Europass and the EU Publications Office.
SDMX, JSON-stat, PxWeb
Standards and tools that statistics offices use to publish tables for programs.
DCAT-AP
The EU’s standard for describing datasets, so that data portals can list them automatically.
Atom feed
A news feed that feed readers check for new entries, similar to RSS.
Language model
Software that writes text by predicting likely words. It is only used in Ask Apprentix, and only on the site’s own data.
EQF, NQF
The European Qualifications Framework and national qualifications frameworks, which place qualifications on levels 1 to 8.
ESCO
The EU’s multilingual classification of occupations and skills.
